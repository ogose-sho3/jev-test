# jev Evaluator（jev 実行画面・実行履歴）

## 目的

TypeSafe の System One モデル **jev**（[API リファレンス](https://docs.typesafe.ai/api)）に、テキスト・ファイルと型付きの質問を送り、構造化された回答を回答形式に応じて表示する社内向けツール。
API 実行ごとの入出力サイズ・実行時間・トークン消費量を記録し、利用状況を確認できるようにする。

## 利用者と権限

- Google アカウントでログインする。**`@sho-san.co.jp` のアカウントのみ利用可**。
- 自分の実行履歴のみ参照できる（他ユーザーの履歴は見えない）。
- 管理者向け機能（全ユーザーの集計など）は現時点では持たない。

## 画面

### ログイン（`/login`）

- 「Google でログイン」で Google OAuth を開始する。アカウント選択画面は `hd=sho-san.co.jp` で絞り込む（見た目の補助のみ）。
- 許可ドメイン外、または OAuth 失敗時はエラーメッセージを表示する。

### 実行（`/`）

- **評価対象（state）**: テキスト、ファイル、またはその両方。
  - テキストのみ → 文字列。「JSON として送信」をオンにすると JSON 値（オブジェクト・配列・文字列）として送る。
  - ファイルのみ → 抽出したテキスト（`.json` はその JSON 値）。
  - 両方 → `{ "text": <テキスト>, "file": { "name": <ファイル名>, "content": <内容> } }`。質問からは `` `text` `` や `` `file.content` `` で参照する。
- **質問（questions）**: jev の仕様どおりの JSON（`{ 質問ID: { type, instructions, criteria } }`）。noul / choice / score のテンプレートを挿入できる。
- **モデル**: `jev-latest`（既定）/ `jev-preview` / `jev-1.13.0`。
- **結果表示**（回答形式ごとに切り替え）:
  - Noul: Yes の確率と横棒。
  - Choice: 選ばれた選択肢、確信度、全選択肢の確率（降順）。
  - Score: 段階値（スケール上の位置）、最も近い段階、確信度、段階ごとの確率。
  - 想定外の形式: 受信した回答をそのまま JSON 表示（将来の形式追加に備える）。
  - 共通: 応答モデル、jev 実行時間、処理全体時間、入出力トークン、リクエスト / レスポンスサイズ、入力サイズ、抽出文字数、質問数。レスポンス JSON 全体も折りたたみで表示。
- 実行ログの保存に失敗した場合でも結果は表示し、警告を出す。

### 実行履歴（`/history`）

- 自分の直近 50 件を新しい順に表示する。集計（実行回数、成功 / 失敗、平均 jev 実行時間、トークン合計）も表示する。

## 入力の制約

| 項目 | 制約 |
| --- | --- |
| テキスト | 200,000 文字まで |
| ファイル形式 | `.txt` `.md` `.csv` `.tsv` `.json` `.pdf` `.docx`（拡張子と先頭バイトで判定） |
| ファイルサイズ | 4MB まで（Vercel Functions のリクエスト上限 4.5MB に収めるため） |
| 抽出テキスト | 400,000 文字まで。テキストが取れない PDF（スキャン画像のみ）は不可 |
| テキストファイルの文字コード | UTF-8（BOM 可）、Shift_JIS |
| 質問 | 200 個まで。Choice は選択肢 2〜255、Score は段階 2〜10（jev の仕様） |

jev 自体の制約（コンテキスト長 state + 最長の質問で 32k トークンなど）を超えた場合は jev が 422 を返し、その内容（項目と理由）を表示する。
jev は英語での精度が最も高く、日本語などは精度が下がる場合がある（[Models](https://docs.typesafe.ai/models#language-support)）。

## データの保持

- **入力テキスト・ファイル内容・ファイル名・回答内容は保存しない**。
- jev を呼び出した実行ごとに `jev_executions` へメタデータを 1 行保存する（成功・失敗とも）。
  - 実行者、日時、結果（成功 / 失敗、エラー種別、jev の HTTP ステータス）
  - 指定モデル / 応答モデル
  - 質問数、入力テキストのバイト数、入力ファイルのバイト数と種別、jev へのリクエストのバイト数、レスポンスのバイト数
  - jev 実行時間（SDK のリトライを含む）、サーバー処理全体の時間（ファイル抽出を含む）
  - 入力 / 出力トークン数（jev の `usage`。取得できない場合は null）
- 入力検証エラーなど jev を呼び出す前に失敗したものは記録しない。
- ログは追記のみ（更新・削除不可）。保存期間は現時点で定めていない。

## 外部サービス

- **TypeSafe jev**: `POST https://api.typesafe.ai/v1/systemone`。公式 JS SDK（`@typesafe-ai/sdk`）を使用。
  - 1 回の試行のタイムアウト 20 秒、429 / 529 / 5xx などは SDK が最大 2 回リトライ（バックオフ、`retry-after` を考慮）。
  - エラーの対応: 400 / 422 → 入力内容のエラー（jev の説明を表示）、429 / 529 → 利用上限、401 / 403 → 呼び出し失敗（API キー不備。詳細は出さない）、タイムアウト → 504、その他 → 502。
  - 料金は入力トークン課金（出力は無料）。
- **Supabase**: Auth（Google OAuth）と Postgres（実行ログ）。

## セキュリティ

[docs/security.md](../security.md) を参照。要点:

- 許可ドメインは 4 層で判定する（Auth フックでのユーザー作成拒否、OAuth コールバック、proxy、各 API）。DB 側でも RLS がドメインを判定する。
- jev の API キーはサーバーのみで使用する。
