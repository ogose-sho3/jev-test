# Review

Review the completed change with priority in this order:

1. Security and data integrity.
2. Functional correctness.
3. Maintainability and responsibility boundaries.
4. Consistency with project rules and canonical documentation.
5. UI/UX and style details.

Findings should be actionable and tied to the relevant file/code. Do not create noise from uncertain or purely stylistic issues unless they matter to the project rules.
